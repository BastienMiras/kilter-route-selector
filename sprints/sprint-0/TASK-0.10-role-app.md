# TASK-0.10 - Ansible role: app

**Sprint** : 0
**Estimation** : 2h
**Priorité** : Haute
**Dépendances** : TASK-0.7, TASK-0.8, TASK-0.9

## Objectif

Créer le rôle Ansible `app` qui déploie le stack kilter sur le VPS via podman-compose : création des répertoires, génération du `.env` depuis template Jinja2, pull des images GHCR, démarrage du compose et health-check.

## Checklist

- [ ] Créer `infra/ansible/roles/app/meta/main.yml`
- [ ] Créer `infra/ansible/roles/app/templates/env.j2` (template Jinja2 du .env)
- [ ] Créer `infra/ansible/roles/app/tasks/main.yml` avec toutes les étapes de déploiement
- [ ] Vérifier que le health-check avec `retries` et `delay` est présent
- [ ] Linter le rôle avec `ansible-lint`

## Exemple de contenu

**infra/ansible/roles/app/meta/main.yml**
```yaml
galaxy_info:
  role_name: app
  description: Deploy kilter app stack via podman-compose
  min_ansible_version: "2.14"
dependencies: []
```

**infra/ansible/roles/app/templates/env.j2**
```jinja2
# Generated by Ansible — do not edit manually
DATABASE_URL=sqlite:///./data/kilter.db
ENVIRONMENT={{ env }}
LOG_LEVEL={{ log_level | default('info') }}
KILTER_API_TOKEN={{ kilter_api_token | default('') }}
```

**infra/ansible/roles/app/tasks/main.yml**
```yaml
---
- name: Create app directory
  ansible.builtin.file:
    path: "/opt/kilter-{{ env }}"
    state: directory
    owner: "{{ deploy_user }}"
    group: "{{ deploy_user }}"
    mode: "0750"
  become: true

- name: Create data directory
  ansible.builtin.file:
    path: "/opt/kilter-{{ env }}/data"
    state: directory
    owner: "{{ deploy_user }}"
    group: "{{ deploy_user }}"
    mode: "0750"
  become: true

- name: Place .env file from template
  ansible.builtin.template:
    src: env.j2
    dest: "/opt/kilter-{{ env }}/.env"
    owner: "{{ deploy_user }}"
    group: "{{ deploy_user }}"
    mode: "0640"
  become: true

- name: Copy compose file for this environment
  ansible.builtin.copy:
    src: "{{ playbook_dir }}/../compose.{{ compose_name }}.yml"
    dest: "/opt/kilter-{{ env }}/compose.yml"
    owner: "{{ deploy_user }}"
    group: "{{ deploy_user }}"
    mode: "0644"
  become: true

- name: Log in to GHCR
  ansible.builtin.command: >
    podman login ghcr.io
    --username {{ ghcr_username }}
    --password {{ ghcr_token }}
  no_log: true
  changed_when: false
  become_user: "{{ deploy_user }}"
  become: true

- name: Pull latest images
  ansible.builtin.command: >
    podman-compose -f /opt/kilter-{{ env }}/compose.yml pull
  become_user: "{{ deploy_user }}"
  become: true
  environment:
    IMAGE_TAG: "{{ image_tag }}"

- name: Start stack with podman-compose
  ansible.builtin.command: >
    podman-compose -f /opt/kilter-{{ env }}/compose.yml up -d --remove-orphans
  become_user: "{{ deploy_user }}"
  become: true
  environment:
    IMAGE_TAG: "{{ image_tag }}"

- name: Wait for health check
  # Le health check passe par Nginx (:app_port) qui strip /api/ avant de
  # transmettre au backend — la requête arrive sur le backend comme GET /health
  ansible.builtin.uri:
    url: "http://localhost:{{ app_port }}/api/health"
    method: GET
    status_code: 200
  register: health
  retries: 10
  delay: 3
  until: health.status == 200
```

**Lint**
```bash
cd infra/ansible
ansible-lint roles/app/
# Expected: no errors
```

## Critères de validation

- `ansible-lint roles/app/` ne retourne aucune erreur
- Le template `env.j2` génère un fichier `.env` valide avec les variables `env`, `log_level`, `kilter_api_token`
- Le health-check `ansible.builtin.uri` utilise `retries: 10` et `delay: 3`
- `no_log: true` est présent sur la task de login GHCR
- Les répertoires sont créés avec les bons droits (`0750` pour les dossiers, `0640` pour `.env`)
- Le rôle utilise la variable `{{ env }}` pour rester générique (dev/staging/prod)
